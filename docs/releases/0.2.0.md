# OpenBao Observability 0.2.0

OpenBao Observability 0.2.0 expands the reference architecture beyond the
initial baseline with stronger metric-contract maturity, richer secret-engine
coverage, multi-instance dashboard filtering, and refreshed local evaluation
dependencies.

The release remains a validated reference architecture and implementation
profile. It is not a drop-in production monitoring distribution. Production
environments still own retention, access control, alert routing, network
isolation, sizing, and audit archive controls.

## Highlights

- Metric contracts now include maturity metadata and profile-aware fixture
  coverage, making required, optional, variable, and topology-specific metric
  expectations clearer.
- KV v2 route observability and secret-engine coverage were expanded, including
  generated recording rules and dashboard updates for feature-specific signals.
- Dashboard filtering now supports multi-instance namespace views, which makes
  shared observability backends easier to use across OpenBao deployments.
- The metric compatibility matrix now documents variable fixture coverage for
  metrics that can appear or disappear across live HA/Raft standby captures.
- The README was shortened into a front door that routes readers into focused
  documentation instead of duplicating the full reference architecture.
- CI now filters reviewed `govulncheck` findings with documented rationale,
  while keeping vulnerability checks active for reachable findings.

## Dependency and profile updates

The local implementation profile and validation toolchain were refreshed:

- OpenBao Docker Compose profile: `quay.io/openbao/openbao:2.5.5`
- Prometheus Docker Compose profile: `prom/prometheus:v3.13.0`
- Grafana Docker Compose profile: `grafana/grafana:13.1.0`
- Grafana Alloy Docker Compose profile: `grafana/alloy:v1.17.1`
- Loki Docker Compose profile: `grafana/loki:3.7.3`
- Go module baseline: Go `1.26.4`
- OpenBao Go API client: `github.com/openbao/openbao/api/v2 v2.6.0`
- Prometheus Go modules: `github.com/prometheus/common v0.69.0` and
  `github.com/prometheus/prometheus v0.313.0`

## Compatibility and validation

Metric contracts, generated artifacts, and the Docker Compose evaluation
profile are validated against OpenBao `2.5.5`. The refreshed fixture capture
preserves the same compatibility-matrix behavior as the previous `2.5.4`
baseline while aligning the release with the current OpenBao patch level.

Generated artifacts continue to support OpenBao telemetry using either the
default Vault-family `vault_*` metric prefix or an `openbao_*` prefix variant.

CI for the release commit runs the repository verification flow, including
fixture capture, generated artifact validation, documentation validation,
Prometheus rule checks, Go tests, linting, vulnerability checks, and whitespace
checks.
