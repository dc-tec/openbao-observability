# OpenBao Observability 0.3.0

OpenBao Observability 0.3.0 adds a native Splunk implementation profile and
expands visibility into expiration backlogs and storage contention. The new
dashboards, alerts, and runbook help operators investigate slow authentication
and writes alongside token activity, cleanup work, and Raft storage costs.

## Native Splunk observability

The Splunk profile includes **15 Dashboard Studio dashboards with 289 panels**,
generated from the same source contracts as the Grafana profile. It covers
service health, HA/Raft, audit investigation, authentication, token and lease
lifecycle, secret engines, storage, Kubernetes, and availability.

The profile uses native SPL searches and Splunk metrics and event indexes.
Collection examples use the OpenTelemetry Collector to deliver OpenBao
telemetry and logs.

An installable `.spl` package contains the dashboards, search macros,
navigation, and **17 native alerts** covering:

- Core health and Raft/Autopilot health.
- Audit request and response failures.
- Expiration backlog growth and backlog with high request latency.
- Selected security investigation signals.

Alerts install disabled, with no outbound notification actions. Configure
deployment scope, execution ownership, and notification routing before enabling
them. The remaining 32 canonical alerts are recorded as unmapped.

## Expiration backlog and storage diagnostics

The token and lease lifecycle dashboard now exposes waiting expiration jobs,
queue trends, dispatch-wait observations, and per-queue detail. New warning
alerts detect sustained backlog growth and backlog that coincides with elevated
request or login latency.

The runtime and storage dashboard adds Raft backend write latency, quorum
commit time, local batch-apply time, pending apply work, and FSM busy wall time.

A new incident runbook explains how to correlate these signals with consumer
activity and application latency. It distinguishes tracked leases from waiting
jobs and net queue change from successful revocation throughput. The lease-count
warning threshold is not a universal performance boundary.

## Validation and compatibility

The Splunk reference implementation is validated on **Splunk Enterprise 10.4.5
with OpenBao 2.7.2**. Checks cover clean archive installation, all 289 panel
searches, calculation fixtures, restricted access, dashboard rendering, and
native scheduled alert firing and recovery. Local AppInspect passes with zero
errors, failures, or warnings.

Splunk Cloud deployment and platform vetting remain unqualified. Production
capacity and external notification delivery require validation in the target
environment.

Repository CI covers OpenBao **2.6.3, 2.7.0, and 2.7.2**. The local Compose
profile updates to OpenBao 2.7.2, Prometheus 3.15.1, Grafana 13.3.0, Grafana Alloy
1.21.3, and Loki 3.7.9.

## Adoption

Grafana and Prometheus users can apply the regenerated dashboards, recording
rules, and warning alerts through their existing deployment process.

Splunk users can install the `.spl` package, configure collection and index
permissions, and follow the profile's validation and alert-activation
procedures. Installing the app does not deploy collectors or create indexes.
